# 企业级平台与运行技术安全落地合同

本模块把“仓库里已有安全代码”和“现场企业平台已经安全运行”严格分开。当前仓库具备 OpenID Connect 联合身份令牌核验、具名主体、角色授权、签名租户上下文、请求限流、哈希链审计和容器加固，但默认仍是单实例、本地文件状态和本地审计。因此默认报告必须保持 `0/9` 来源、`0/20` 闸门和 `blocked`，不能把配置模板当成高可用、灾难恢复或运行技术安全证据。

设计基线采用 [NIST SP 800-63C-4 联合身份与断言](https://csrc.nist.gov/pubs/sp/800/63/C/4/final)、[NIST SP 800-207 零信任架构](https://csrc.nist.gov/pubs/sp/800/207/final) 和 [NIST SP 800-82 Rev.3 运行技术安全指南](https://csrc.nist.gov/pubs/sp/800/82/r3/final)。这些标准用于约束证据和验收，不代表本软件获得任何认证。

## 可执行联合身份和租户边界

`API_AUTH_MODE=oidc` 时，后端执行以下检查：

- 只接受 `Authorization: Bearer` 中三段式、`alg=EdDSA` 的 JSON Web Token。
- 按 `kid` 从 `OIDC_PUBLIC_KEYS_JSON` 选择 Ed25519 公钥并验证完整签名输入。
- 精确校验签发方、受众、签发时间、生效时间、失效时间、最大令牌年龄和时钟偏差。
- 默认要求 `amr` 中存在多因素、硬件密钥或一次性口令证明。
- 通过 `OIDC_ROLE_MAP_JSON` 把外部角色映射为 `viewer`、`operator`、`admin`。
- 从签名的租户声明读取允许组织；多组织用户必须发送 `X-Tenant-ID`，且所选组织必须属于令牌声明。
- 把具名主体、角色、租户和认证方式写入结构化访问日志与变更哈希链，不记录令牌或密钥。
- `GET /api/security/context` 可供入口网关和验收测试核对当前主体及租户上下文。

公钥为可轮换的信任材料，不得把私钥或长期令牌放入仓库。生产环境应由企业入口或身份感知反向代理完成授权码流程、会话安全和令牌更新，再把短期访问令牌传给本服务。

## 九类独立证据来源

| 来源域 | 必须提供的现场证据 |
| --- | --- |
| `identity_provider` | 身份提供方配置、两个以上活动签名密钥、多因素认证、令牌正反向测试、离职回收、休眠账户和应急账户演练 |
| `authorization_and_tenant_control` | 具名用户与角色绑定、最小权限、特权复核、职责分离、跨租户拒绝、行级安全、租户分区和独立租户密钥 |
| `message_and_timeseries_platform` | 三节点消息仲裁、持久化、幂等生产、确认消费、模式登记、死信、重放演练、时序复制、留存、备份导出和租户分区 |
| `ha_orchestrator` | 多应用实例、多工作实例、多可用区、数据库副本、负载均衡健康检查、自动切换、防脑裂和单故障容量 |
| `backup_dr_platform` | 加密、不可变、异地和离线备份，恢复哈希、恢复点目标、恢复时间目标及恢复手册演练 |
| `worm_siem_platform` | 外部一次写入多次读取留存锁、哈希链、时钟同步、脱敏、投递率、检测规则、演练工单和检测时延 |
| `pki_key_management` | TLS 版本、用户/API、服务间、信息技术/工业隔离区、工业隔离区/运行技术四条双向 TLS 边界，证书清单、密钥轮换、吊销、密钥托管和硬件根密钥 |
| `ot_security_monitor` | 企业信息技术区、工业隔离区、运行技术控制区、安全仪表区，默认拒绝、允许通道、只读网关、跳板机、远程会话记录、资产清单、漏洞治理、事故演练和独立安全联锁 |
| `enterprise_governance` | 获批安全架构、租户策略、运行技术风险评估、适用标准版本，以及企业负责人、首席信息安全官和运行技术安全负责人三方批准 |

每类载荷由其责任系统独立使用 Ed25519 私钥签名。服务端从 `ENTERPRISE_SECURITY_PUBLIC_KEYS_JSON` 获取公钥；仓库默认 `{}`。`scripts/sign_enterprise_security_evidence.py` 只帮助现场生成签名证据包，私钥不得进入仓库。

## 二十项失效关闭闸门

1. 九类来源恰好各一份。
2. 每类完整载荷的 SHA-256 和 Ed25519 签名有效。
3. 全部来源是现场实数、未超时且在允许的跨源时间窗口内。
4. 安全架构、租户策略、运行技术风险评估和标准版本获批。
5. 联合身份签发方、受众、轮换密钥及有效/无效令牌测试齐备。
6. 普通与特权用户多因素认证、自动停权、休眠和应急账户闭环。
7. 具名用户、角色绑定、最小权限和拒绝测试通过。
8. 职责分离及特权访问复核通过。
9. 行级安全、分区键、独立租户密钥和跨租户拒绝率达到 100%。
10. 消息集群至少三节点并具备仲裁、持久化、幂等、确认、模式、死信和重放，投递确认率至少 99.9%，重复业务影响为零。
11. 时序平台至少双节点、复制因子至少二、留存不少于 30 天，备份导出和租户分区已验证。
12. 应用、工作服务、数据库和可用区均无单点，负载均衡、自动切换和防脑裂齐备。
13. 故障切换实测满足可用性目标和恢复时间目标，单故障后仍保留 100% 目标容量。
14. 备份加密、不可变、异地、离线且保留不少于 30 天。
15. 恢复演练通过、数据哈希一致，并满足恢复点和恢复时间目标。
16. 外部一次写入多次读取留存锁、哈希链、脱敏、时钟和至少 99.9% 日志投递率通过。
17. 至少五条安全信息事件管理检测规则完成演练，产生工单且检测时间不超过 15 分钟。
18. 四条双向 TLS 边界、证书有效性、最大密钥年龄、轮换、吊销、密钥托管、硬件根密钥和秘密扫描全部通过。
19. 四个运行技术安全分区、默认拒绝、只读网关、出站允许清单、跳板机、多因素认证、会话记录、临时供应商访问及至少 95% 资产/漏洞治理覆盖通过。
20. 运行技术事故演练、独立安全联锁、本地人工控制、应用无命令权和三方职责分离批准全部通过。

## 接口和状态

- `GET /api/dashboard/enterprise-security`：返回当前仓库控制与现场核证值分离的失效关闭状态。
- `POST /api/dashboard/enterprise-security/evaluate`：验证九源证据并输出 20 道闸门、输入哈希和报告哈希。
- `GET /api/security/context`：返回当前具名主体、角色、允许租户、选定租户和认证方式，不返回令牌。
- `blocked`：至少一个业务或安全闸门失败。
- `reconciled_pending_source_attestation`：17 项现场控制计算通过，但来源覆盖、签名或时效仍未全部可信；不释放 `verified_*`。
- `evidence_package_passed`：九源和 20 道闸门全部通过后才释放核证摘要。

## 永久生产边界

即使证据包通过，本模块也只提供评估报告，以下字段始终为假：

- `automatic_security_configuration_allowed=false`
- `enterprise_cutover_authorized=false`
- `ot_command_authority=false`
- `safety_interlock_bypass_allowed=false`
- `security_certification_claim_allowed=false`
- `production_authority=false`

现场投产还需要企业身份提供方、入口网关、消息与时序集群、数据库、高可用编排、备份平台、PKI/密钥平台、安全信息事件管理和运行技术网络设备真实部署；完成故障切换、恢复、密钥轮换、检测响应和本地人工接管演练；由企业负责人、首席信息安全官和运行技术安全负责人共同签署切换单。本仓库不会自动配置防火墙、证书、数据库、消息集群或可编程逻辑控制器，也不会取代独立安全联锁。
