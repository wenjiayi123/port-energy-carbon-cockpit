# 可审计能源与碳管理体系证据合同

## 能力边界

该模块把组织级能源与温室气体管理所需的证据组织成可复算、可签名、失败关闭的年度闭环。版本基准为 `ISO 50001:2018`、`ISO 50001:2018/Amd 1:2024` 和当前发布版 `ISO 14064-1:2018`。

软件只校验证据合同、先后关系、职责分离、完整性与签名，不复制受版权保护的标准条文，不解释认证准则，也不充当认证机构、温室气体核证机构或监管报送主体。即使 15 个门禁全部通过，`iso_50001_certified`、`iso_14064_1_verified` 和 `regulatory_submission_allowed` 仍固定为 `false`；真实认证或核证结论必须由获授权的独立机构在系统外出具。

## 十五个门禁

### 计划

1. 组织环境、组织与运营边界、适用要求登记簿、气候变化相关性评审和标准版本锁定。
2. 最高管理者批准并沟通能源与碳方针，明确持续改进、信息和资源承诺。
3. 最高管理者、能源经理、温室气体清单责任人、运营责任人和内部审核员五类职责齐备，内部审核员与运行职责分离。
4. 能源评审识别主要能源使用、相关变量、仪表和运行控制，并校验主要能源使用覆盖率。
5. 能源基准的周期、冻结时间、调整触发条件、标准化方法和批准记录完整。
6. 能源绩效参数、目标值、当前值、责任人、期限及批准记录一一对应。

### 实施

7. 每个目标均有行动计划、预算、资源、责任人、期限和完成证据。
8. 监视测量计划覆盖主要能源使用仪表，数据完整率达到批准阈值，并引用校准、修订和计量核证证据。
9. 每个主要能源使用均有唯一运行准则、责任人和异常响应。
10. 五类责任人员均有在管理周期内有效的能力评估和意识确认。

### 检查

11. 温室气体清单锁定组织边界、报告边界、基准年、七类港口排放源、因子登记簿、不确定度、重算触发条件和修订编号，并引用碳清单与计量核证证据哈希。
12. 内部审核在周期结束后完成，覆盖能源管理和温室气体清单，审核员不得兼任运行职责。

### 改进与独立保证

13. 每个审核发现必须有唯一纠正措施、根因、责任人、关闭时间和有效性验证；无发现时必须提供具名声明哈希。
14. 最高管理者在审核和纠正措施关闭后完成管理评审，输入覆盖绩效、目标、监测、清单、审核、纠正措施和资源，输出决定及资源批准。
15. 独立保证方使用配置的 Ed25519 公钥验证整个证据包；任意字段被改动后签名立即失效。

## 状态机

- `blocked`：前 14 个管理闭环门禁至少一个未通过。
- `management_cycle_ready_pending_independent_assurance`：管理闭环完整，但可信公钥、独立性、结论或签名未通过。
- `evidence_package_passed`：15 个门禁全部通过，仅表示系统收到并验证了完整证据包，不表示获得 ISO 认证或温室气体核证意见。

## 接口

- `GET /api/dashboard/energy-carbon-management`：返回当前场景的声明安全状态。公开离线数据默认 `0/15`、`blocked`。
- `POST /api/dashboard/energy-carbon-management/evaluate`：校验现场证据包并返回输入哈希、报告哈希、逐门禁结果和阻断码。

独立保证公钥配置格式：

```bash
export MANAGEMENT_SYSTEM_AUDITOR_PUBLIC_KEYS_JSON='{"assurance-key-2026":"BASE64_ED25519_PUBLIC_KEY"}'
```

签名工具：

```bash
PYTHONPATH=backend backend/.venv/bin/python scripts/sign_energy_carbon_management_evidence.py \
  --input unsigned-management-cycle.json \
  --private-key independent-assurance-private.pem \
  --key-id assurance-key-2026 \
  --output signed-management-cycle.json
```

私钥必须由独立保证方保管，不应进入应用配置、代码仓库、前端或日志。生产接入还应由独立机构确认取证程序、抽样范围、重要性、认证/核证范围和适用法规。
