# 实港投产总门禁与现场实施手册

## 1. 结论边界

本模块解决“各功能单独通过，但整体仍不能安全投产”的问题。它把十三个实施域、现场运行实测、回滚与灾备演练、人员培训和六方批准绑定到同一个港口、租户、验收窗口、数据截止时点及目标发布版本。

默认状态必须是 `blocked`、`0/13` 现场验收域和 `0/16` 总门禁。仓库中已有的报告哈希只证明相应代码和离线合同存在，不等于现场验收。

当十六道门禁全部通过时，状态是 `eligible_for_external_cutover_review`，含义仅为“材料可以提交外部变更委员会审查”。以下权限仍固定为假：

- `automatic_cutover_allowed=false`
- `production_dispatch_allowed=false`
- `production_authority=false`
- `interlock_bypass_allowed=false`

实际切换只能由港口外部生产指令网关、独立可编程逻辑控制器联锁和获授权的现场人员完成。

## 2. 十三个投产域

| 域 | 现场责任方 | 接受条件 |
| --- | --- | --- |
| `live_port_data` | 数据平台与各源系统所有者 | 六类适配器、签名、时效、顺序、单位、复合快照和重启重发通过 |
| `measurement_and_calibration` | 计量负责人 | 分路计量与标定覆盖 100%，能量守恒、账单和作业量对账满足阈值 |
| `production_execution` | 生产控制负责人 | 外部指令网关、设备能力检查、超时降级、设备回执和独立联锁通过 |
| `long_horizon_shadow` | 运营与模型风险负责人 | 至少 180 天、旺淡季和六类规定异常场景完成只读影子运行 |
| `port_emissions_inventory` | 碳盘查负责人 | 完整源类、边界、因子、不确定度和独立保证通过 |
| `energy_carbon_management` | 能源管理负责人 | 能源基准、能源绩效参数、目标、纠正措施、管理评审和独立保证闭环 |
| `operations_energy_coupling` | 码头运营负责人 | 船期、泊位、岸桥、堆场、车辆、冷藏箱、岸电与储能联合计划核验 |
| `electrical_network` | 港口电力负责人 | 拓扑、潮流、电压、无功、谐波、热老化、N-1、孤岛、充电与储能约束通过 |
| `algorithm_production` | 模型风险负责人 | 多种子跨季节、概率预测、分布外检测、解释、可达性、时限、故障注入与人工否决通过 |
| `carbon_asset_compliance` | 碳资产负责人 | 登记簿、配额、绿证、交易和履约证据核验；系统不自动交易或申报 |
| `commercial_settlement` | 财务与结算负责人 | 账单、需量、电价、需求响应、购电协议、租户分摊、量测与验证及投资经济性通过 |
| `port_collaboration` | 港航协同负责人 | 准时到港、岸电预约计费、绿色泊位、替代燃料、激励和收益共享通过 |
| `enterprise_ot_security` | 首席信息安全官与运行技术安全负责人 | 身份租户、消息时序、高可用灾备、WORM/SIEM、PKI、分区和联锁通过 |

每个域必须提供独立 Ed25519 签名，签名身份通过 `SITE_CUTOVER_TRUSTED_SIGNERS_JSON` 同时绑定公钥和唯一责任域。一个责任域的密钥不能替另一个域签字。

## 3. 十六道总门禁

1. 十三个域恰好各一份，不允许缺失或重复。
2. 每个域的内容摘要和责任方 Ed25519 签名有效。
3. 所有报告绑定同一港口、同一租户和同一验收窗口。
4. 数据截止点在窗口内、跨域偏差不超过 24 小时，报告时效不超过 30 天。
5. 十三个域均由独立责任方接受，且没有未关闭例外。
6. 至少六类实时适配器全部可用，累计至少 1,000 个签名快照和 100 个原子复合影子快照。
7. 分路计量及标定覆盖率均为 100%，能量平衡误差不超过 1%，账单对账误差不超过 0.5%。
8. 影子运行不少于 180 天，覆盖至少两个运营季节及旺季、淡季、极端天气、设备故障、电网降额和计划检修。
9. 外部生产指令网关、设备能力检查、可编程逻辑控制器联锁、100% 设备最终回执和超时降级通过。
10. 人工接管和回滚演练通过，回滚时间不超过策略阈值。
11. 备份恢复演练通过，实测恢复点目标和恢复时间目标满足策略。
12. 网络安全事件演练通过，未关闭的一级和二级缺陷均为零。
13. 操作员培训覆盖 100%，规程、运行手册、变更单和切换窗口获批。
14. 节能减排效益已由独立量测与验证接受并绑定效益归因报告。
15. 港口负责人、运营负责人、能碳负责人、运行技术安全负责人、首席信息安全官和独立核证人六方签名，且签名绑定完整包摘要。
16. 应用本身没有生产授权、物理调度或联锁绕过能力。

摘要不匹配、内容被签后修改、域与密钥权限不匹配时直接 `blocked`。只有完整内容摘要正确、但现场公钥尚未配置时，才允许显示 `reconciled_pending_attestation`。

## 4. 接口与签名工具

- `GET /api/dashboard/site-cutover-readiness`：显示仓库报告与现场验收分离的默认总状态。
- `POST /api/dashboard/site-cutover-readiness/evaluate`：复算十三域、十六门禁和六方签名。
- `scripts/sign_site_cutover_package.py`：由各责任方在安全环境中签署模块和批准记录，并导出只含公钥的可信签名者配置。

私钥、长期令牌、现场证书和生产配置不得进入仓库。签名工具的输出仍需通过安全信息事件管理、一次写入多次读取存储和变更工单留存。

## 5. 现场实施顺序

### 阶段 A：基础设施与责任边界

1. 确定港口、码头、组织租户、资产清单、数据所有者和控制责任人。
2. 部署身份入口、消息集群、时序数据库、关系数据库、高可用编排、备份、密钥平台、WORM/SIEM、工业隔离区和跳板机。
3. 建立开发、测试、影子、预生产和生产五套隔离环境；冻结配置与基础设施代码哈希。
4. 由外部生产指令网关和独立联锁保有全部物理控制权。

### 阶段 B：只读接入与计量标定

1. 接入终端操作系统、能源管理系统、船舶/泊位、设备、气象航行和岸电兼容性六类源。
2. 核对事件编号、时间、单位、质量、修订、源记录和签名；重启后要求全源重发。
3. 完成岸桥、场桥、车辆、冷藏箱、岸电、储能、建筑和电网分路计量及校准。
4. 连续完成能量守恒、电表、账单和作业量对账。

### 阶段 C：长周期影子与故障注入

1. 全程只读运行至少 180 天，不向现场设备下发指令。
2. 覆盖旺淡季、极端天气、设备故障、电网降额和计划检修。
3. 对比现行规则、模型预测控制和强化学习候选；记录建议、接受、拒绝、越权、超时和人工否决。
4. 完成高可用切换、灾备恢复、密钥轮换、安全事件、人工接管和回滚演练。

### 阶段 D：预生产验收

1. 十三个责任域分别生成最终报告及哈希，并独立签名。
2. 冻结目标发布版本、配置、基础设施代码、规程、运行手册和安全论证。
3. 关闭所有一级、二级安全缺陷和所有验收例外。
4. 六方对同一完整包摘要签字，禁止拆分或签后替换附件。

### 阶段 E：外部变更委员会切换

1. 外部变更委员会核对本系统输出、现场工单、联锁状态、人员在岗和回滚负责人。
2. 现场人员在获批窗口操作外部指令网关；本应用仍保持建议与评估角色。
3. 任一监控、回执、联锁、时间同步、数据质量或安全门禁异常时立即停止并按手册回滚。
4. 切换后继续保留人工接管、不可改写日志、效益归因和定期再核证。

## 6. 必须由业主提供的外部条件

仓库无法自行补齐以下事实：真实港口系统账号和网络许可、设备协议与点表、现场电表与校准证书、生产控制网关、可编程逻辑控制器联锁、集群和灾备资源、企业公钥基础设施、安全信息事件管理、WORM 留存、操作员排班、演练时间、审批人身份以及最终变更窗口。这些条件缺少任何一项，总门禁都会保持失效关闭。

## 7. 现场交付包与填写校验

`deployment/site_delivery/` 提供一套受控模板，覆盖：

- 十三类源系统和适配器映射，明确事件、时间、单位、质量、修订、源记录与回执字段；
- 岸桥、场桥、场内车辆及充电、冷藏箱、岸电、储能、建筑、电网、变压器和馈线点表；
- 信息技术区、信息技术隔离区、运行技术隔离区、运行技术控制区及独立安全联锁区；
- 每项活动唯一最终负责方的职责分工矩阵；
- 连续 180 天、两个运营季节及六类规定场景的影子验收计划；
- 十三域、十六道门禁、六方批准、未签名接口包和可信公钥配置骨架。

运行 `make site-delivery-check` 只验证模板结构、覆盖范围和应用失效关闭边界。现场填写完成后运行：

```bash
backend/.venv/bin/python scripts/validate_site_delivery_kit.py deployment/site_delivery --strict
```

严格模式要求消除全部占位符和零摘要，所有映射、点表、网络记录、影子证据及职责活动获接受，十三域无例外并独立核证，十六门禁全部通过，六方对同一包摘要签字，且接口复算结果达到 `eligible_for_external_cutover_review`。严格模式通过仍不会把 `production_authority` 改为真。
