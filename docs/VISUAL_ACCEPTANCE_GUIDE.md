# 本地可视化验收指南

本指南用于在发布前人工检查 v0.3.0 的算法、数据、业务指标和实港安全边界。
全程只查看本地系统；不要点击“训练”，除非你明确准备启动一个真实 learner 任务。

## 0. 启动

在 macOS Terminal 中执行：

```bash
cd "/path/to/port-energy-carbon-cockpit"
bash scripts/start_demo.sh
```

等待终端同时出现以下标志：

```text
Demo is running:
  Frontend: http://127.0.0.1:5173/
  Backend:  http://127.0.0.1:8808/api/health
```

浏览器打开 `http://127.0.0.1:5173/`。检查结束后回到该终端，按 `Control+C` 停止前后端。

## 1. 首屏检查：数据质量不再等于落地质量

等待约 3–8 秒，直到首屏有数据。检查：

- 顶部 KPI 的数据质量显示“离线 A · 落地 D”。
- 底栏显示 `PORT FEEDS: 0/6`、`AUDIT CHAIN: INTACT`、`PRODUCTION DISPATCH: DISABLED`。
- 标题上方显示“公开离线基准 · 等待接入港口”。

变化点：旧版只容易看到数据完整度；新版同时暴露离线研究质量和实港落地等级。

优化意义：43,848 行不再被误读为 43,848 条独立实港观测。系统按 1,238 条官方逐日锚点计算 35.418 行/锚点，并因缺少真实 TOS/EMS/设备字段保持 D 级和生产禁用。

## 2. 打开新增业务证据

在中间“测试轨迹回放”标题栏点击高亮的“证据 / Evidence”。右下角“场景推演”区域也保留了同一证据入口；不要点击旁边的“训练 / Train”。

弹窗最上方应出现“V4 因果落地评测 · 新增业务证据”，并看到：

- 48 窗口 × 24 小时，共 1,152 个因果留出步骤。
- MPC 深度：H6、Beam 8、27 个候选动作。
- 数据密度：43,848 行 / 1,238 个官方锚点。
- 相对固定全资源基线：能耗下降 8.73%，碳排下降 8.79%，成本下降 8.09%，峰值下降 2.98%，吞吐保留 99.9828%。
- 碳排 95% CI：8.39%–9.25%；成本 95% CI：7.62%–8.60%。

变化点：业务指标不再只是单个点估计，评测面板直接显示样本规模、因果协议和置信区间。

优化意义：这些指标可由报告、数据哈希和代码哈希复算，且明确标注为公开数据离线证据，不冒充现场 KPI。

## 3. 检查算法增量与负面结果

在同一证据板中检查两栏：

- “相对因果旧 MPC 的算法增量”：延误下降 43.88%，P95 队列下降 47.86%，动作抖动下降 25.44%，硬约束成功 100%。
- “公开代价 · 不隐藏负结果”：碳排增加 0.1557%，成本增加 0.1911%，峰值增加 0.3942%，实港等级 D、生产禁用。

继续看三个压力卡：需求 +15%、电网降额 10%、设备降额 15% 均为 100% 零建模硬越界；电网降额卡必须同时显示“软储备缺口 +7.692%”。

变化点：新增风险感知 MPC 的价值落在排队、延误和动作稳定性，而不是宣传所有维度全面变好。

优化意义：保留不利结果能证明评测没有挑指标，也能为真实港口的安全裕度校准提供研究问题。

## 4. 检查算法和训练边界

在弹窗向下查看“五算法矩阵”：PPO、SAC、TD3、DQN 和 MPC 必须同时存在。

底部应显示：

- 训练渲染 `OFF`。
- 测试回放 `HELD-OUT ONLY`。
- 连续动作 4 个，DQN 离散动作 81 个。
- 当前已注册策略的生产资格为“禁止”。

变化点：训练、测试、渲染和策略准入成为不同阶段，不再由前端动画代替训练证据。

## 5. 检查 API、实港快照和审计链

关闭 RL 弹窗，点击页面右上角服务器图标。检查 API 与模型治理面板：

- “只读实港快照”显示 0/6，而不是模拟为已连接。
- “快照完整性”显示失败关闭。
- “审计链”显示完整。
- “生产调度”显示已禁用。
- RL 路由列表显示后端真实接口状态。

变化点：新增六源签名只读快照、重放/时效/序列门禁和 SHA-256 审计链状态。

优化意义：在没有港方密钥与数据时系统保持不可执行，避免“换个 CSV 就能直控设备”的虚假落地结论。

## 6. 检查 3D 测试轨迹和可视化联动

关闭弹窗，在中间“测试轨迹回放”区域：

1. 港区右侧应固定显示 B01–B04，当前泊位为绿色；左上只显示一个当前测试步卡片。
2. 蓝色归一化测试航迹、船舶和泊位应位于同一地图层，不应出现悬空直线或重复船舶卡片。
3. 点击右下角 `＋`，底图、航迹、船舶和泊位必须同步缩放；点击 `⌖` 恢复默认视角。
4. 点击暂停按钮，轨迹应冻结在当前 STEP；点击播放后应继续推进。
5. 点击任一时间节点，船舶、泊位、岸桥、集卡、岸电状态和单步指标应同步变化。
6. 页面始终显示 `HELD-OUT TRAJECTORY REPLAY`、`PUBLIC TEST SPLIT · NOT LIVE` 和 `NOT A LIVE SCHEDULE`。

变化点：缩放现在作用于统一地图世界层；没有真实空间坐标支撑的 AGV/集卡伪路线、重复悬浮卡片和无数据风速装饰已移除。

优化意义：当前仅保留可复用的港区渲染、泊位节点、测试航迹、资源动作和缩放交互。实港接入时替换地图与坐标适配器即可，不需要推翻核心交互；公开数据阶段也不会冒充真实地理轨迹。

## 7. 查看可审计原始证据

在新标签页打开：

- `http://127.0.0.1:8808/api/evidence/landing-benchmark`：v4 指标、压力结果、边界和哈希的机器可读摘要。
- `http://127.0.0.1:8808/api/health/ready`：数据、运行时、审计链和只读接入就绪状态。
- `http://127.0.0.1:8808/docs`：OpenAPI 接口清单。

原始完整逐窗口证据仍在 `reports/port_landing_benchmark_v4.json`，API 为避免传输约 200 KB 明细，明确返回 `per_window_evidence_included=false` 和原文件路径。

## 8. 验收记录

建议逐项记录：通过/不通过、看到的数值、截图文件名、异常现象。确认视觉和业务表述都符合预期后，再通知维护者统一提交并推送 GitHub。
