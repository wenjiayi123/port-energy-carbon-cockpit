# 港航生态协同与绿色航运走廊证据闭环

本模块把码头内部优化扩展到具名船舶、船公司、港口、岸电运营方、替代燃料设施和绿色航运走廊治理方。公开船舶日报扩展数据仍只作为 `scenario` 展示；只有七类来源独立签名、现场实数标记和十五项闸门全部通过，报告才会变为 `evidence_package_passed`。

## 七类必须独立签名的来源

| 来源域 | 必须提供的业务证据 | 典型责任系统 |
| --- | --- | --- |
| `vessel_operator_plan` | 国际海事组织船舶编号、原始预计到港时间、建议发出时间、协商到港时间、实际到港时间、剩余航程、基准与建议航速、燃油和船公司接受回执 | 船公司航次管理与船舶性能系统 |
| `port_call_platform` | 码头就绪、泊位窗口、系妥、开工、完工和离港里程碑 | 港口调用优化平台、船舶交通服务系统 |
| `terminal_berth_operations` | 绿色资格、优先级分数、同组排序、泊位分配规则和批准记录 | 码头操作系统、泊位计划系统 |
| `shore_power_operator` | 逐船逐泊位预约、兼容性、容量、服务窗口、收入电表、账单和结算回执 | 岸电运营与计费系统 |
| `alternative_fuel_facility` | 燃料类型、库存、输送能力、许可证、兼容设备、人员、安全论证、风险评估、应急演练和服务回执 | 替代燃料设施与安全管理系统 |
| `port_tariff_authority` | 绿色港口费规则、基准费用、折扣、应付金额、账单和付款回执 | 港口费率与财务系统 |
| `corridor_governance_ledger` | 走廊章程、参与方、减排主张、独立核证、收益分配规则、双边批准和结算回执 | 绿色航运走廊治理台账 |

签名覆盖各来源拥有的完整业务载荷，不只签汇总数。公钥通过 `PORT_COLLABORATION_PUBLIC_KEYS_JSON` 注入；仓库默认 `{}`，因此默认必然失效关闭。`scripts/sign_port_collaboration_evidence.py` 要求七个来源分别使用 Ed25519 私钥，私钥不得进入仓库。

## 十五项失效关闭闸门

1. 七类来源恰好各一份，不能缺失或重复。
2. 每类载荷的 SHA-256 摘要与 Ed25519 签名有效。
3. 来源记录均标记为现场已核实，且满足最大时效与跨源时间对齐窗口。
4. 绿色航运走廊章程、港口、协作窗口、币种、分配比例和批准记录齐备。
5. 国际海事组织船舶编号、船公司、目的港和船舶调用编号在所有业务对象间一一贯通。
6. 船公司明确接受准时到港建议，建议发出早于协商到港时间并满足最短提前量。
7. 实际到港偏差不超限，建议航速不高于基准航速，剩余航程与航时一致，实际燃油不高于基准并可重算减排量。
8. 码头就绪、泊位窗口、系妥、开工、完工、离港时间顺序与船舶到港记录一致。
9. 绿色泊位分数必须按获批的准时到港、岸电和替代燃料权重重算，同一公平组内排序一致并留有批准记录。
10. 岸电预约绑定同一船舶、泊位和作业窗口，船岸兼容，预留功率不超泊位容量，计量电量不超服务窗口物理上限。
11. 岸电账单按 `计量电量 × 单价 + 接电费` 重构，币种、状态和结算回执一致。
12. 替代燃料属于走廊准入清单，库存和输送能力覆盖需求，许可证有效，设备、人员、安全论证、风险评估和应急演练均通过，且已有服务回执。
13. 绿色港口费折扣按三类资格重算、不超封顶比例，应付金额和付款回执一致。
14. 每船三类减排主张编号唯一且均已独立核证；准时到港主张与燃油重算值一致，收益总额和船港分成完整对账。
15. 港方与船公司由不同责任人分别批准同一走廊章程，不允许单方自批。

## 核心计算

- 准时到港提前量 = `协商到港时间 − 建议发出时间`
- 预计航时 = `剩余航程海里 ÷ 建议航速节`
- 到港偏差 = `|实际到港时间 − 协商到港时间|`
- 准时到港燃油节省 = `基准燃油吨 − 实际燃油吨`
- 准时到港减排 = `燃油节省吨 × 船用燃料排放因子千克/吨 ÷ 1000`
- 绿色泊位分数 = `准时到港资格 × 权重 + 岸电资格 × 权重 + 替代燃料资格 × 权重`
- 岸电账单 = `计量电量千瓦时 × 电价 + 接电费`
- 替代燃料最大服务量 = `最大输送速率吨/小时 × 服务小时`
- 绿色港口费折扣 = `min(三类资格折扣之和, 总折扣上限)`
- 共享减排价值 = `独立核证减排量 × 每吨二氧化碳当量价值`
- 港方/船公司收益 = `共享减排价值 × 章程约定比例`

所有金额使用政策中的统一币种；金额误差受 `maximum_amount_variance_pct` 控制。减排主张编号和每船类别必须唯一，避免同一减排量重复参与收益分配。

## 接口与状态

- `GET /api/dashboard/port-collaboration`：返回当前失效关闭状态；公开船舶活动和岸电情景值与核证值分列。
- `POST /api/dashboard/port-collaboration/evaluate`：核验七源证据，重算准时到港、泊位、岸电、替代燃料、港口费和收益分配，输出逐项闸门、输入哈希和报告哈希。
- `blocked`：至少一个业务计算或证据闸门失败。
- `reconciled_pending_source_attestation`：业务记录可重算，但签名、公钥、时效或现场实数门槛未通过；不释放核证汇总值。
- `evidence_package_passed`：七类来源和十五项闸门全部通过后，才释放 `verified_*`。

## 生产边界与现场落地

证据包通过只说明材料在当前规则下可复核，不授予软件任何船舶或港口生产权限。模块始终保持：

- `vessel_speed_instruction_allowed=false`
- `berth_plan_writeback_allowed=false`
- `shore_power_switching_allowed=false`
- `fuel_bunkering_authorization_allowed=false`
- `port_invoice_issue_allowed=false`
- `financial_transfer_allowed=false`
- `production_authority=false`
- `human_acceptance_required=true`

正式上线还需要走廊参与方签署章程与数据协议；船公司、港口调用平台、码头、岸电、燃料设施和财务系统完成身份及主数据映射；岸电表计和燃油计量完成校准；完成平行航次、账单、收费、减排主张及收益分配对账；由港方、船长或船公司、码头调度、岸电操作员、燃料安全负责人和财务人员完成职责分离验收。船舶航速、泊位计划、岸电合闸、燃料加注、开票和资金划转仍由各外部责任系统与有权人员执行。
