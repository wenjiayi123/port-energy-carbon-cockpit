# 商业结算、量测核证与边际减排成本闭环

本模块把离线情景价值与可进入财务复核的商业证据彻底分开。公开数据中的区域平均电价、用户输入碳价和需求响应工程事件继续显示为 `scenario`，不得进入 `verified_*` 字段。只有八类来源逐源签名、现场实数标记和十六项闸门全部通过，报告才会变为 `evidence_package_passed`。

## 八类必须独立签名的来源

| 来源域 | 必须提供的原始证据 | 典型权威系统 |
| --- | --- | --- |
| `utility_tariff_invoice` | 生效分时电价、需量费、固定费、税费、公用事业账单及付款回执 | 公用事业客户门户、财务应付系统 |
| `revenue_metering` | 收入级电表区间电量、需量、质量码、源记录号和载荷哈希 | 电能管理系统、计量数据管理系统 |
| `demand_response` | 获批基线、承诺和实测削减、绩效、罚金、运营方结算单与到账回执 | 需求响应聚合商或市场运营方 |
| `ancillary_services` | 出清容量、服务时长、绩效、罚金、结算单与到账回执 | 电力市场运营方 |
| `power_purchase_agreement` | 购电协议、交付量、合同价、账单与付款回执 | 购售电合同与财务系统 |
| `renewable_certificate_registry` | 唯一证书编号及序列段、持有人、受益人、期间、注销状态和回执 | 绿证登记簿 |
| `tenant_billing` | 租户分表、分摊规则、分项金额、租户账单和状态 | 租户计费系统 |
| `investment_and_mv` | 独立复核的量测核证报告哈希、获批资本开支、运维增量、措施节能量、双人审批 | 量测核证档案、资本项目和财务审批系统 |

签名覆盖各来源拥有的完整业务载荷，而不是只签一个自报总数。公钥通过 `COMMERCIAL_SETTLEMENT_PUBLIC_KEYS_JSON` 注入，仓库默认 `{}`，因此默认必然失效关闭。`scripts/sign_commercial_settlement_evidence.py` 要求八个来源分别提供 Ed25519 私钥；私钥不进入仓库。

## 十六项可执行闸门

1. 八类来源恰好各一份，不能缺失或重复。
2. 每类载荷的 SHA-256 摘要与 Ed25519 签名有效。
3. 签名时间满足时效和跨源对齐窗口，且全部声明为现场已核实数据。
4. 电价合同覆盖整个结算期，币种一致，全部电表时段均有合同费率。
5. 收入电表区间数量、实测覆盖率、唯一编号、计量边界和期间完整。
6. 从区间电量和最大需量重构能源费、需量费、固定费、税费和总额，并逐项与账单对账。
7. 公用事业账单必须为已付款且有付款回执。
8. 需求响应按承诺容量、实测削减、事件时长、绩效和罚金重算，并与已结算金额对账。
9. 辅助服务按出清容量、服务时长、绩效和罚金重算，并与运营方结算单对账。
10. 购电协议交付电量乘合同价并加固定费，与账单和付款回执对账。
11. 绿证编号与序列段唯一，受益人、结算期和币种一致，状态为已注销且有回执。
12. 每个租户分项之和等于租户总额；全体租户的电量、同时需量和金额分别与总表及可分摊成本对账。
13. 节能量和减排量只能引用 `independently_reviewed` 的量测核证报告，并绑定报告编号、期间和 SHA-256。
14. 措施编号和节能主张编号唯一，资本开支、运维增量和投资批准齐备；各措施节能量之和与量测核证报告对账。
15. 使用合同分时电价和需量费计算年度净收益、简单投资回收期；使用年金化资本开支计算并排序边际减排成本曲线。
16. 财务负责人和能源经理必须由不同人员分别批准同一个计算规则哈希。

## 账单、回收期和边际减排成本公式

设区间电量为 `E_i`，所属分时时段价格为 `p_i`，结算期最大需量为 `D_max`，需量单价为 `p_d`：

- 能源费 = `Σ(E_i × p_i)`
- 需量费 = `D_max × p_d`
- 税费 = `(能源费 + 需量费 + 固定费) × 税率`
- 账单重构总额 = 能源费 + 需量费 + 固定费 + 税费
- 措施年度净收益 = 年化分时节能价值 + 年化需量节省 + 已结算激励 − 年度运维增量
- 简单投资回收期 = 资本开支 ÷ 年度净收益
- 年金化资本开支 = `CAPEX × r(1+r)^n ÷ ((1+r)^n − 1)`；`r=0` 时为 `CAPEX ÷ n`
- 边际减排成本 = `(年金化资本开支 + 年度运维增量 − 年度节能价值 − 已结算激励) ÷ 年度核证减排量`

曲线按边际减排成本从低到高排列，并累计年度减排量。相同 `savings_claim_id` 会触发重复主张闸门，防止一个节能量同时进入多个投资项目。

## 接口与状态

- `GET /api/dashboard/commercial-settlement`：返回当前默认的失效关闭状态，公开情景值与核证值分列。
- `POST /api/dashboard/commercial-settlement/evaluate`：验证证据、重算结算、输出逐项闸门、输入哈希和报告哈希。
- `blocked`：至少一个业务计算或证据闸门失败。
- `reconciled_pending_source_attestation`：业务计算通过，但签名、公钥、时效或现场实数门槛未通过；只释放 `calculated_*`。
- `evidence_package_passed`：八类来源和十六项闸门全部通过，才释放 `verified_*`。

## 生产边界

通过证据包不等于软件取得银行、电力市场、绿证登记簿或会计系统权限。模块始终保持：

- `payment_instruction_allowed=false`
- `market_bid_allowed=false`
- `certificate_trade_allowed=false`
- `tenant_invoice_issue_allowed=false`
- `accounting_posting_allowed=false`
- `production_authority=false`
- `human_release_required=true`

正式上线还必须由港方、财务、电力市场、登记簿及租户计费责任人完成接口授权、主数据映射、计量校准、并行账期对账、异常退回、人工复核和会计入账验收。本仓库提供可执行合同和失效关闭机制，不代替这些外部授权。
